# ColorLab — лабораторная работа №1, вариант 10

CMYK ↔ LAB ↔ RGB. Выполнены базовое задание и дополнения для подгруппы 10А: ручная математика, D65/D50/E, вычисляемые матрицы, UCR/GCR, Clipping/Scaling, динамические градиенты, MVC и автотесты.

## Запуск

На Windows запустите `ColorLab.exe` из корня проекта. Это самостоятельная сборка: Python и зависимости на компьютере преподавателя не нужны. Проверка на другом физическом ПК остаётся рекомендованной проверкой переносимости.

В PyCharm используйте `.venv\Scripts\python.exe`, точка входа — `main.py`.

На новом компьютере для запуска исходников:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python main.py
```

## Управление

- Во всех трёх моделях доступны числа, ползунки и двумерная палитра. Фиксированные координаты палитры указаны над ней.
- Поля принимают точку или запятую. Пересчёт — после 450 мс, Enter или потери фокуса. Стрелки двигают выбранный ползунок, Home/End задают границы.
- Градиент каждого ползунка показывает результат изменения его компоненты при текущих значениях остальных. Штриховка обозначает выход за sRGB.
- D65 — средний дневной свет, D50 — тёплый дневной, E — равноэнергетический источник. RGB всегда sRGB. При смене белого пересчитываются матрицы и LAB; отображаемый RGB обычно сохраняется. Если адаптированный LAB выходит за диапазон полей, ввод ограничивается с предупреждением.
- UCR выделяет чёрный в глубоких тенях с ослаблением для цветных участков; GCR выделяет серую компоненту во всём диапазоне. Переключение меняет рецепт CMYK, сохраняя RGB. Введённый вручную CMYK сохраняется до изменения другого представления или алгоритма.
- Clipping обрезает каналы. Scaling линейно сжимает общий диапазон каналов; при отрицательных значениях также сдвигает его. Исходный LAB вне охвата сохраняется, а RGB/CMYK/образец показывают приведённый цвет. Оба способа учебные, не перцепционно оптимальные.
- «Матрицы» показывает текущие вычисленные прямую и обратную матрицы; окно обновляется при смене освещения.
- «Сброс» возвращает начальный цвет, сохраняя выбранные настройки. «Копировать HEX» копирует цвет образца.

## Архитектура

| Файл | Ответственность |
|---|---|
| `color_models.py` | Model: формулы, ручные матричные операции, адаптация, цветоделение, охват |
| `controller.py` | Controller: состояние, проверка ввода, синхронизация, настройки и выборки цветов |
| `main.py` | View: виджеты, события и рисование |
| `test_colors.py`, `test_extended.py` | Математические и контроллерные тесты без GUI |
| `test_ui.py` | Интеграционные тесты виджетов; нужен Tk/Windows |
| `REPORT.md` | Теория, формулы, параметры алгоритмов и сценарий защиты |
| `build.py`, `ColorLab.spec` | Воспроизводимая сборка одного EXE |

Model и Controller не импортируют Tk, CustomTkinter или Pillow. Pillow используется только для рисования и изменения размера изображений. NumPy, colorsys, ImageCms, ICC-конвертеры и другие библиотеки цветовых преобразований не используются.

## Тесты

```powershell
.venv\Scripts\python -B -m unittest -v test_colors test_extended
.venv\Scripts\python -B -m unittest -v test_ui
```

Всего 36 тестов: 31 тест математики/контроллера и 5 интеграционных. Случайные проверки воспроизводимы: 2000 исходных + 6000 для всех комбинаций освещения и алгоритма. Тестовые эталоны отделены от рабочих вычислений.

## Сборка

```powershell
.venv\Scripts\python -m pip install -r requirements-build.txt
.venv\Scripts\python build.py
```

`build.py` сначала запускает весь набор тестов, затем собирает `ColorLab.exe` в корень и создаёт `BUILD_INFO.json` с SHA-256 исходников и EXE. Рабочие файлы сборки размещаются в `build/current`. Старый каталог `dist`, если он остался от прежней версии, не является актуальной сборкой.

Перед сдачей заполните ФИО и группу в `REPORT.md`; разместите исходники на GitHub самостоятельно. Готовый EXE передавайте отдельно от исходников либо через GitHub Releases.
